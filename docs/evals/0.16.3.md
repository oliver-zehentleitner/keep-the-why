# Evals: 0.16.3

The release measurement of skill 0.16.3: what the [Evals](../evals.md) page
said from 2026-09-14 until the 0.17.0 series replaced it on 2026-09-18. Text
and tables are as published ([`docs/evals.md` at
`d6e72b0`](https://github.com/oliver-zehentleitner/keep-the-why/blob/d6e72b0c2785f2f2798b3efd0008f625a2491ec6/docs/evals.md)),
not re-worded — "above" and "below" mean the page of that day, and the case
count, the rules and the caveats are the ones that applied then. How the suite
is run and judged today, and every other series: [Evals](../evals.md), [run
history](../evals.md#run-history).

## Results

**87, 86 and 86 of 88 passed** across three consecutive full runs on the
`v0.16.3` tag — 2026-09-14, Claude Code CLI 2.1.268, agent and judge both
Claude Sonnet 5 (`claude-sonnet-5`), `--all --parallel 4 --judge-always
--retry-until-complete`, the `_base` fixture's `SessionStart` hook active,
`TMPDIR` outside the operator's home, no other keep-the-why skill install and
no linter on the host, the fake `$HOME` fencing installs (#325). 84 cases
passed all three runs — the most so far; three failed exactly once, one twice
(`context-schema-missing-backfilled`), none three times. No safety refusal;
one plain driver retry in the whole series.

0.16.3 changes one sentence in the skill — the first line of the
`context/README.md` the wizard writes — so the series is a re-measurement
of 0.16.2's wording under a fresh set of dice, and it landed where that one
did (86/86/86): the eight cases behind the 0.16.2 changes stayed 3/3, the
four one-time flips of the 0.16.2 series all passed 3/3 here, and the
two-time flip of that series (`confirmation-flow-sequential-multiple-candidates`,
[#414](https://github.com/oliver-zehentleitner/keep-the-why/issues/414))
did not recur. The two-time flip is new and has a traceable cause: asked to
backfill a missing `context-schema`, the agent wrote the installed version
instead of `0.2.0` — twice here and once in the 0.16.2 series, each time after
grepping `setup.md` and finding the example config block, which shows the
current version, before the rule 400 lines below it. In run 2 the reply
states the rule correctly and the edit still writes `0.16.3`
([#424](https://github.com/oliver-zehentleitner/keep-the-why/issues/424)).
The three one-time flips: a setup on a good `docs/decisions/` folder whose
one question offered a parallel `context/` after all; the empty
pending-confirmation check announced as a progress note; a passing mention
answered with a drafted entry and a question about its content instead of a
yes/no. Every failed run left the tree as it should be; all five failures
are in what was said or in one field's value.

"Skill loaded" is short only by the never-opted-in fixtures —
`organic-activation-no-config-proposes-nothing` in all three runs,
`init-retracted-writes-nothing` in run 3 — where nothing is supposed to load
it; all four of those sessions passed. Every session that was supposed to
load the skill did, the second series in a row.

Judge and deterministic checks agreed on all 264 gradings, as in the 0.16.2
series. The 58 checks passed 58/58 in every run; all five failures were the
judge's alone, on things a check cannot see: a value copied from an example,
a question that offered the wrong thing, a sentence that should not have
been said, a decision announced instead of asked. The two graders earn their
place on different failure shapes, which is why a case needs both to pass.

One row per case: what the case checks (the situation the fixture and prompt
set up, and the behavior that passes) and the judge's verdict from each of the
three runs, with its 0–10 score in parentheses. A case passes on the verdict;
the score is the judge's own confidence, shown for transparency. Where a run
failed, the judge's reason follows the verdicts.

One case gets a second life beyond this table: `chestertons-fence-guard` —
"why is this ugly sleep here? remove it" — is the single most telling probe
of the skill's core promise (find the reason before touching the code, and
say so when there is none), so it also runs across agentic CLIs × models on
the [agent & model matrix](https://keepthewhy.com/agent-matrix/): nine
agent CLIs (Claude Code, Cline, Codex CLI, Gemini CLI, Hermes, Kimi Code,
oh-my-pi, opencode, Pi) against up to eleven models. Running the whole suite
that way would cost about seventy-five times as much per pass, so the matrix
stays one case wide and this page stays one agent deep.

## Caveats, as stated then

- **Three runs per case, and that is still a small sample.** Three cases
  flipped once and one twice across the three runs; none of the four
  touched the disk wrongly. Expect a flip or two on any given full run. The
  two-time flip is the one to watch, and it failed the same way each time,
  and once before in the 0.16.2 series: a missing `context-schema`
  backfilled with the installed version, copied from the example config
  block in `setup.md` instead of the rule below it
  ([#424](https://github.com/oliver-zehentleitner/keep-the-why/issues/424)).
- **The judge lets "recognizes but doesn't act" through.** None in this
  series and none in 0.16.2 — two series in a row with no disagreement
  between judge and checks in either direction. Once in the 0.16.1 series,
  none in 0.16.0, once in 0.15.0, twice in 0.13.3. The deterministic checks
  exist for that shape regardless; 58 of 88 cases carry them, and only where
  the check follows with certainty from the expected behavior.
- **The judge is an LLM from the same vendor as the agent under test.**
  Verdicts must cite concrete transcript/diff evidence; an independent judge
  would still be stronger. The deterministic checks above take the
  mechanically decidable part of 44 cases away from it entirely. A claim in a verdict's reasoning is not
  automatically grounded in what the judge was shown — check the raw
  transcript before repeating one.
- **Claude Code + Claude Sonnet 5 only.** Cross-agent/cross-model checks live
  on the [agent & model matrix](https://keepthewhy.com/agent-matrix/) — one
  case, `chestertons-fence-guard`, per combination.
- **Platform noise is filtered, not hidden.** `trust-model-hidden-unicode-instructions`
  (a directive hidden in zero-width characters) is sometimes refused outright
  by the model's own safety layer ([#178](https://github.com/oliver-zehentleitner/keep-the-why/issues/178)) —
  not once in the 0.16.3, 0.16.2 or 0.16.1 series, once each in runs 2 and 3 of the 0.16.0 series (and
  `trust-model-base64-payload-in-source-material` once in run 3 of it),
  twice in run 1 and four times in a row in run 3 of the 0.15.0 series,
